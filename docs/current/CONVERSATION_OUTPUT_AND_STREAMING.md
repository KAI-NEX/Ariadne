# 对话文件输出与流式回复

更新：2026-09-10。当前实现为模型按请求选择交付形式，普通聊天不附导出按钮。真正 Provider 流式与创作型图片生成仍未接入。

## 当前：按意图交付文件

- 四个领域 Runtime / 六个页面共用 `src/conversation_delivery.py` 与 `public/conversation-output.js`。在原本同一次模型结构化回复中增加可空的 `deliverable`，不增加意图分类调用、不用本地关键词判断用户意图，不修改选定模型、推理强度或工具权限。DISTILL / SYNTHESIZE 不参与交付。
- 普通聊天、解释文件格式、明确只要文字：`null`，只显示文字。要求介绍文件、报告等：`PDF`，由模型写完整文档内容并自动本地排版下载。要求流程图/关系图：`DIAGRAM`，模型给节点和有向边，Canvas 生成真正的图解 PNG，显示预览、可点击放大及下载。
- 照片、插画等创作型图片与其他未实现格式：`UNSUPPORTED`，明确说明能力未接入，不用文字截图或图解冒充。当前未启用 Codex 的 `image_generation`，未接入图片生成服务。
- 交付契约 `ariadne-conversation-delivery-v1`：精确键 `kind/title/body/nodes/edges`；标题至多 100 UTF-16 单元，PDF 正文 20000，图解说明 1200，暂不支持说明 400；图解 1–8 个节点（每个 70）、最多 12 条边（标签 28）。拒绝越界、自环、重复边、外加 URL/路径/脚本字段。内容只作文本/绘图数据，不执行模型代码。
- 先通过原领域动作、身份、版本与来源范围校验，再接受文件；文件契约错误明确失败。前端也校验契约与版本，文件提案随成功助手消息/turn 原子持久化，不进入确认 Candidate/Job。历史记录没有此字段仍正常打开；重开由已保存的提案重新生成 Blob，无需再次调用模型。旧对话不自动补生成文件。
- 各领域的相关历史上下文可带有界文件摘要，明确标记为非确认、可能截断；沿用各域的版本/撤回过滤。不是完整文件记忆或无界上下文，长文件的后半内容可能不在后续请求中。
- 本地生成按目标消息串行处理，避免同时创建多个画布；页面移除/重绘丢弃迟到结果并回收 Blob URL。失败没有下载链接，只显示错误与“重试生成文件”。不自动下载到磁盘，用户点击下载入口决定保存。
- PDF 暂仍采用现有 Canvas/JPEG A4 排版：中文完整、分页，但文字不能选取或搜索，暂无可访问文本层。图解为有界节点连线，不是任意复杂工程图/绘画平台。所有文件保持非确认信息说明，不因下载变成核实事实。

### 当前验收

- `tests/conversation_delivery_regression.py`：四领域交付接线、单次调用、非法文件/领域失败、Local 拒绝、非对话阶段隔离；既有四域 Runtime、Codex 身份/强度与保存边界回归继续通过。
- `tests/conversation_output_regression.mjs` 及个人理解/职位概况/Candidate 集成回归覆盖文件校验、消息持久化重开、不写确认资料、PDF 字节结构、边界与重复标题处理。
- 合成资料真实 Codex / gpt-5.6-sol、medium 测试：普通文字、介绍文件、流程图、创作型照片四种请求分别得到 null / PDF / DIAGRAM / UNSUPPORTED；单次样本耗时约 12–21 秒，不是性能基准，也不代表真实流式。未上传私人资料、修改浏览器选定的运行配置。
- egolite 六页面共用渲染实际检查：普通消息零按钮、文件自动生成下载链接；使用真实模型合成内容生成 PDF/PNG 并下载、检查 A4 PDF 和中文页面。运行与 QA 文件保留 `.cache/conversation-delivery-20260910/`。这些 UI 检查注入合成回复，不把它们描述为六入口真实 Provider 端到端验收。

## 历史：最初的逐条导出阶段（按钮已被上方交付模式替代）

- 六个对话入口复用 `ConversationUI` 按需加载 `conversation-output.js/css`。每条助手回复可生成 PDF 或分页 PNG，提供下载链接和图片预览。
- 输出来自所选回复正文，不调用 Provider、不执行 HTML/SVG/脚本、不读取服务器路径，不将回复写入确认 Candidate/Job。它是本地排版导出，不是模型原生返回的二进制文件，也不是生成式图片或语义图表。
- 浏览器 Canvas 使用现有 VI 字体链和颜色渲染中文及混排；A4、分页、页码、非确认信息说明。PDF 嵌入页面 JPEG，**文字不可选取、搜索，暂无可访问的文本层**。保留原始对话正文，不能声称这是完整的简历编辑/排版器。
- 最多 4 万 UTF-16 代码单元、32 页；文字作为文本处理，不执行标签。生成失败显示错误，不出现虚假下载。链接在当前页面有效；刷新后可重新生成，下载的文件由用户保管。重绘、移除及重新生成回收旧 Blob URL。
- 对话发送状态显示真实经过时间及结束耗时，不提供猜测的百分比。保留现有阶段文案及前端完整结果校验；去掉 `waitForIndicatorPaint` 默认 800 ms 固定停顿，只等浏览器绘制。

## 慢回复的已定位原因与未完成边界

1. `src/codex_runtime.py` 当前隔离的 `codex exec --json` 路径等待子进程完成，之后解析最终 `agent_message`。前端各领域调用 `response.json()` 等整包。
2. 职位概况在资料或执行配置变化时可能先进行分批 DISTILL / SYNTHESIZE，再 DISCUSS。个人理解已在另一阶段改为当前上下文单次 DISCUSS，不强制先重建画像。
3. `ConversationUI.revealReply` 是拿到完整合规回复后的快速逐字呈现，不是真正流式。本阶段没有把它重新命名为流式，也没有更换模型、推理强度或降低内容校验。

本机 Codex 0.153.4 的 App Server 协议支持 `item/agentMessage/delta` 和结构化 `outputSchema`，但 `app-server` 没有当前 exec 路径使用的 `--ignore-user-config / --ignore-rules` 开关。本次只运行 initialize/config/read，不创建模型线程、不请求模型、不输出凭据：即使关闭现有 feature 列表，配置中仍有两个继承的 MCP server 条目。条目的存在不是工具实际执行的证据，但也不能据此宣称新路径具备现有隔离保证。因此没有将 App Server 替换进生产调用。

## 真正流式的后续验收条件（未实施）

- 独立连接显式隔离用户配置、规则、MCP、插件、hooks、skills、额外指令与工具，保留既定 Provider/model、凭据边界、只读与零工具调用约束；不要以扩大电脑操作权限换取流式。
- 通过原有多模态 authority 核验新协议：真实合成 PNG、完整视觉 PDF、结构化最终输出与对抗性材料的隔离回归。不能只做文本连通测试后替换现有 adapter。
- 请求级事件串包含 phase、公开回复增量、elapsed、终止结果；只输出公开答复，不输出原始推理、完整工具参数或未校验修改。传输增量是临时预览，不能成为确认记录。
- 最终完整 JSON 继续执行领域契约、来源/范围、执行代次和版本校验；成功才替换预览并落入既有历史/Working 流程。失败、断流、取消、迟到结果必须清除或明确标记预览，不能保存未完成动作。
- 先到字时间、首段早于终止事件、断连、超时、交错请求和 Connector 权限均需验证。真正流式可缩短首字等待，但不能消除资料预处理或模型内部推理时间。
- PDF/有界图解已按本页当前交付契约实现；AI 创作图片仍需要经过 capability 验证的生成 adapter，不能直接取消目前禁用 image_generation 的设置。
