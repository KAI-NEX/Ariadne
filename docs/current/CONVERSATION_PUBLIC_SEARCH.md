# 对话公开搜索与个人经历隔离

2026-09-24。用户要求：允许搜索，但网上信息不能混淆个人经历。本次范围为本机 Ariadne Skill 的 Codex 对话；公开 Web 的自带 API 通道没有因此获得搜索能力。

## 可用范围

2026-09-24 后续流式升级：正式通道改为独立登录目录的 `CODEX_APP_SERVER`，typed `webSearch` 事件转换为下述同一搜索回执并保留全部修改禁令。新增真实合成搜索验收通过；此前 exec JSONL 的记录保留为历史。账号/有效隔离策略与连续文字边界见 [对话实时反馈](CONVERSATION_LIVE_FEEDBACK.md)。

Candidate 列表/详情、Job 列表/详情、了解我、职位概况的 DISCUSS 请求，经服务器验证 Codex credential 后才开启 `web_search=live`。普通个人讨论不必搜索；需要最新招聘信息、公开研究或核对事实时按需调用。Candidate/Job 导入、DISTILL、SYNTHESIZE 与 Local 不开启搜索；BYOK 请求不注入此能力。

沿用已合格的 `gpt-5.6-sol` 和该对话的推理强度。Codex 从独立临时目录运行，不复用唤起 Skill 的 Agent 会话或工具管道。当前验收 CLI 为 `0.155.0-alpha.16.3`：实际搜索需要同时开启本次进程的 `code_mode` 和 `code_mode_host`，否则真实探测报 host disabled。其他 shell、apps、插件、浏览器控制、多代理开关继续关闭；未修改用户全局 Codex 配置。JSONL 只接受已有消息事件和限定的 web_search 事件，出现其他工具活动立即失败并终止子进程，不把这一事后检查描述为操作系统级工具隔离。

## 信息和保存规则

- 模型必须区分个人原件/已保存自述、外部网页的说法、比较推断与未知。职位要求、公司成果、同名者页面、公开项目均不能自动证明用户做过相应工作。
- 提示词要求只发送必要的公开职位、公司、技能、地点等查询词，不将私人材料原文、联系方式、凭据或未公开项目提交搜索。这是模型指令边界，当前 CLI 托管搜索不提供 Ariadne 在调用前逐条审核查询词的接口；不能声称已实现确定性脱敏。
- 只要本轮出现搜索事件，最终领域结果必须是解释/澄清且没有 `patches`、`proposals`、`card_proposals` 或 `job_edit`。代码拒绝违规结果，不进入 Working/记忆/确认资料流程。无搜索的独立修改回合仍走现有用户原话、来源、版本和人工保存校验。
- 搜索回执 `ariadne-public-search-v1` 由运行事件产生。没有完成的 search/open/find 事件时，模型不能靠填写 URL 获得有效来源回执。最多 12 个搜索工具事件、6 条公开 HTTP(S) 来源。
- CLI JSONL 的搜索事件未提供完整结果 URL 列表；来源 URL 来自模型结构化引用，因此标为 `MODEL_CITED`，不能声称逐条完成工具结果交叉核验。回执证明发生过调用，不能证明招聘仍开放或每条外部陈述真实。
- 界面单独显示「外部网页参考 · 不属于个人经历 · 未写入资料」及来源链接；无可用来源时明确显示未取得来源。来源写入对话记录，不能写入个人事实。历史编译继续保留外部参考标记，模型不能把“保存刚才那段”等指代视为新的个人经历自述。
- 仍需对模型语义错误保持可纠正性；结构校验不是语义正确性证明。未实现网页内容自动导入、自动改简历、自动投递或后台检索。
