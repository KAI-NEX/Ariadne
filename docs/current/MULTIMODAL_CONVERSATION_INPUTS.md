# 资料格式与对话附件

更新：2026-09-10。保持当前 Provider/model、来源和人工保存边界，不扩展为通用文件或电脑操作 Agent。

## DOCX 导入修复

原问题是三个不一致：选择器允许 DOCX，选择后却切到未接通的 Candidate 文字操作；按钮资格和前后端 source validator 又只允许 PDF/图片。即便后端理解成功，结果校验还要求至少一张 PDF 渲染页。现将 DOCX 接入既有多模态 Candidate 操作，并使用专门的 `docx_text_and_embedded_images_v1` 回执，零 PDF 页不冒充已渲染页面；已保存来源菜单支持 DOCX/图片恢复。

原始 DOCX 仍先完整保存在浏览器 SourceDocument；服务器只做 ZIP/XML 技术读取，向模型发送正文、表格段落、页眉/页脚/脚注/尾注文字及内嵌 PNG/JPEG。语义理解仍由模型完成，不执行宏、外部链接或 Office 对象。此路径不是 Word 页面排版渲染；含图表、SmartArt、嵌入对象或不支持的图片时明确要求导出 PDF，不静默丢弃。加密、损坏、压缩包预算超限、空材料均明确失败。

## 六个共用入口

| 页面 | 领域与权限 |
| --- | --- |
| 个人资料导入后的工作区、个人资料详情 | Candidate：附件可供解释或已有字段的草稿修改，不自动生成确认版本 |
| 职位导入后的工作区、职位详情 | Job：附件可供职位讨论与已有允许的职位修改，不回写个人事实 |
| 了解我 | 个人理解：附件可供讨论；个人补充仍须满足用户原话与人工保存规则 |
| 了解职位概况 | 职位集合只读讨论；附件不是新建或保存职位的快捷入口 |

每个入口复用 `conversation-attachments.js/css`：文件选择、拖放、输入框内粘贴图片、图片缩略预览、移除、独立传输确认、失败保留及当前轮发送回执。普通文字粘贴不受影响。Local 模式不能发送附件到 Provider。

支持 PDF、DOCX、PNG、JPG/JPEG、UTF-8 TXT、Markdown。每轮最多 4 个附件、单个和合计最多 30 MB；展开后合计最多 48 张图片/PDF 页、12 万字符文字。PDF 使用既有完整逐页图像路径，超过预算就失败，不截取首页冒充完整理解；模型传输的单张图片还受 20 MB 限制。

## 传输与保存

- 现有文字上下文契约保持，增加可选且独立版本化的 `ariadne-conversation-attachments-v1` 当前轮通道。前端先检查专用能力端点；后端核对模型资格、执行 ID、显式 Provider/model 确认、文件类型/字节数/hash、总量和解码结果。
- 选中文件不会立即发送。发送前在独立浏览器 IndexedDB `ariadne-conversation-attachments-v1/turns` 保存原件和当前领域/会话/执行关联，标记 `SOURCE_INPUT_ONLY`；保存失败则不发送。不会把二进制塞入文字上下文、个人记忆或已确认资料。
- Provider 只接收必要文件名、正文、图片和页码，不接收本地凭据、文件路径或附件存储键。附件中的文字不是用户指令；修改权限不因附件而提升。结果仍由各领域既有校验与保存路径处理。
- **附件仅供本轮使用**，后续历史不自动重新传送原件；需要模型再次查看原附件时重新添加。当前没有附件历史浏览/导出菜单，刷新后不会自动恢复待发送选择。原件记录保留在浏览器，不声称已同步到个人资料。
- 原有本机 HTTP 隔离和配对连接器鉴权继续生效，连接器只新增附件能力 GET 白名单，未开放任意文件读取或代理权限。

## 使用

导入 DOCX：添加个人材料 → 选择 DOCX → 使用模型分析 → 确认传输 → 核对工作区 → 人工保存。

对话附件：展开「附件」选择或拖入文件，也可在输入框粘贴图片 → 核对预览与所选模型 → 勾选附件传输确认 → 输入问题并发送。只选附件直接发送时，界面补入「请解读本轮附件」。个人理解/职位概况保留其原有整体资料传输确认。

验收区分离线传输替身、真实 Codex 合成测试、独立浏览器和用户资料；具体结果见 [项目状态](../../PROJECT_STATUS.md)。不因一个 Provider 的实测而宣称所有其他 Provider 的真实运行质量均已验证。
