# Ariadne 内容架构复核与简化

日期：2026-09-12。初次复核基线：`00109ae`；Local 原件归档调整基线：`f761cd6`。目标：保留现有内容与模型功能，减少中间转换和重复编排；人通过卡片浏览和编辑，AI 按范围读取多份 Markdown，原件与来源关系长期保留。

用户随后明确调整：本地识别最初用于学习，现在 Local 只需保存原件，等有 AI 再分析。此决定收缩正常 Local 功能，不再把保留本地分析当作迁移前提。用户已确认的是上述方向及功能保留要求。本文的分层、迁移顺序和实现方式是本次工程判断，不把具体文件结构或数据库切换说成用户已经逐项验收。

## 2026-09-12 迁移完成后的当前状态

本机现已使用真实 Markdown 文件库，网页端使用同格式的浏览器 Markdown 库；卡片、两域保存、个人补充、会话附件、投递和历史页面接入同一存储边界。旧 IndexedDB 原地保留为备份，当前读写不双写。四类对话/理解 Runtime 已读取按范围编译的 Markdown，原件视觉导入和领域保存契约保持。实际目录、迁移触发、恢复方法、验证及未覆盖范围见 [Markdown 内容库与卡片存储](MARKDOWN_CONTENT_STORAGE.md)。

下文“第一轮”和“Local 原件归档”的阶段状态保留为演进依据，后续当前实现以该存储契约为准。

## 结论

当前产品的主要运行结构是一个本机 Python HTTP 服务、原生网页和浏览器本地存储。复杂度主要集中在内容的多种表示、页面编排、不同领域的重复流程及历史兼容，而非多个部署服务。

来源、人工保存、版本冲突、领域范围和真实模型执行保护需要继续保留。这些保护不要求长期维持所有现有中间数据表示。目标可收敛为五项职责：**文件与内容库、卡片界面、上下文准备、模型执行、修改保存**。职责数量不等于文件或数据库表数量。

第一轮复核时，数据仍以 IndexedDB 领域记录为权威，仅完成运行简化；当时的更短模型调用路径不是存储切换。随后主存储迁移已按本文完成条件实施，详见上方当前状态。

## 现状规模与必要性

基线已跟踪 `public/` 有 64 个 JavaScript 文件，`src/` 有 28 个 Python 文件；页面主编排 `public/v1-pages.js` 为 4,181 行，HTTP 入口 `app.py` 为 2,423 行。六类领域 Runtime 包括个人/职位导入、两域对话、个人理解及职位概况。不同文件并不都是独立系统，也不能只凭行数判为多余。

按十二类职责复核：五类保留保护、五类合并实现、一类按规模启用、一类隔离历史兼容。这个统计衡量职责的处理方式，不是可删除代码的比例。

保留原件或审计历史主要增加存储，不应意味着每轮都把它们全读一遍或全部发送给模型。缓存是性能辅助，不是第二份个人事实。

## 目标结构

| 职责 | 唯一负责的事 | 不应承担的事 |
| --- | --- | --- |
| 文件与内容库 | 原件、文档正文、来源定位、版本、当前有效文档目录 | 自动把模型推断升级为确认事实 |
| 卡片界面 | 列表、详情、字段编辑、对话与修改预览 | 维护一份脱离文档的独立语义正文 |
| 上下文准备 | 选择当前范围，编译本轮文档、必要历史与附件，标明覆盖 | 用关键词和模板冒充语义理解 |
| 模型执行 | 沿现有 Provider/模型配置理解资料、回答、提出有类型的修改 | 任意读本机目录、直接确认写盘 |
| 修改保存 | 检查目标和基准版本，预览，人工保存，保留旧版本 | 根据一句普通讨论静默改写资料 |

正常讨论路径为“选中范围 → 读取当前内容 → 模型回答”。请求修改时，回答可附带修改草稿，经原有审阅和保存步骤生效。原件导入先保存 durable SourceDocument；可以停在归档状态，稍后由用户选择原件并确认 AI 分析，才进入现有视觉 PDF/图片/DOCX 技术准备与模型理解。

这些是模块职责，不增加通用 Agent 平台、消息总线、新服务或向量数据库。六个现有对话入口可继续存在；共用执行机制并不要求合并它们的权限。

## Markdown 与卡片怎样共用内容

多份文档按资料、经历、项目、个人补充、职位、分析自然增长。目录名称不是产品逻辑，稳定文档身份和领域才决定如何加载。

- Markdown 保存正文；每份文档保留必要的文档身份、领域、版本、确认状态以及原件/区块引用。机器状态可放少量元数据，不必全部写进用户正文。
- 一份原件可对应多个内容区块；一个文档也可引用多个原件。保留来源顺序、页码/区块定位、缺失标记及用户补充来源，不能只靠标题匹配或文件名链接。
- 卡片字段映射到稳定内容区块，卡片重绘和保存由代码处理。模型负责理解和提出修改，不负责每次重建卡片布局。
- 自由正文、现有字段、未知和来源引用都必须有无损映射。未被卡片展示的文档段落仍保留；不能用一次摘要替代完整正文后宣称无损。
- 用户确认资料、用户偏好、未确认草稿、模型分析分别标记身份。模型分析文档可以引用经历，但不能因为存在于同一个文件夹而被当成经历证据。
- AI 普通对话读取明确选入本轮的 Markdown 内容；导入或视觉核对仍可需要原始 PDF/图片。不能为了“只读 Markdown”丢弃视觉 PDF 路径。
- 外部编辑文档要经过显式导入/差异审阅，且与卡片编辑共享版本检查。自动把任意磁盘变更当成用户已确认资料会改变现有保存权限，不纳入默认方案。

Markdown 是目标内容主体，而不是长期与数据库正文并行维护的第二份真源。卡片所需的轻量索引可重建，投递阶段、会话和模型执行状态仍可使用结构化存储。

## 第一轮已落地的运行简化（历史阶段）

1. **完整资料优先。** 个人资料选择在全部当前语义能放入该调用预算时不再排序截取；职位概况同样完整提供预算内且不超过 60 条的当前 Job。超预算保持原有有界选择和覆盖说明。完整指当前所存的语义记录，不表示每轮重新读取原始 PDF。
2. **小集合单次职位对话。** 未缓存或缓存失效的小集合只执行 DISCUSS，不再先 DISTILL/SYNTHESIZE。不同模型配置的旧概况不注入本轮；正常对话不制造新概况记录。
3. **大集合保留全部职位理解。** 详细上下文发生遗漏/节选时，继续检查并按需更新全体当前职位摘要，再回答；无变化时复用缓存。显式刷新仍保留。
4. **共用技术步骤。** 个人理解和职位概况复用相同的分批函数及模型配置身份函数，保留原分批参数和缓存身份字节格式。

该第一轮未迁移数据库、未改 Provider/model 或提示版本，没有新增应用依赖、数据表或网络服务。模型输入当前仍是既有领域结构化上下文；不能把以上改动称作“AI 已改读 Markdown 文件”。

## 第二轮落地：Local 仅保存原件（历史阶段）

正式导入收敛为 **选材料 → 保存原件 → 可选 AI 分析 → 人工保存卡片**。移除页面内两域本地提取/结构化编排及 OCR 探测，不再产生“未接 AI 但已理解材料”的流程。Local 仍可浏览和编辑既有内容。

- Candidate 和 Job 共用原件归档；文件 bytes、身份、hash、文件名保留。粘贴的职位文本原样保存，空行与首尾空格不再被裁掉。
- 使用现有 `source_documents` store 保存一个轻量来源组索引，记录有序 source IDs、来源链接和时间。无新表、无模型状态、无语义正文；已有文件和旧单文件记录可直接恢复。重复保存同一顺序/链接幂等，不靠文件名混淆来源。
- 两个导入页共用原生原件选择框；刷新后恢复原件，职位按原顺序恢复材料组。Candidate 仍逐份分析受支持的图片/PDF/DOCX，TXT/Markdown 可归档；未扩展模型 adapter 的文件支持范围。
- Model 不可用时仍能显式保存；可用时也能选择稍后分析。模型执行仍需原资格和传输确认，失败只报告失败，不自动运行本地分析。
- 保存失败不显示成功；成功保存的单份原件保留，可重试完成来源组。历史卡片、草稿、对话与底层学习模块保留，不新增本地识别的结果。

这一步当时只减少正常路径的维护范围，未改变主存储；第三轮已完成下方条件的代码、合成迁移与模型验收。跨浏览器、跨 origin 自动恢复仍未实现。

## 存储迁移的验收依据

迁移应以“所有功能继续读写同一内容”为交付单位，不能先换主存储再逐项补救。

1. 建立现有 Candidate、Job、个人补充与分析内容到文档区块的对应清单，包括卡片字段、可编辑项、原件和来源位置、草稿、确认、移除、撤回及历史。
2. 用合成数据验证“当前记录 → Markdown 文档 → 原有卡片投影”的往返不丢内容、不变身份、不丢来源。此阶段旧存储仍为唯一主存储；生成的文档是可检查的迁移产物。
3. 接通同一个文档读写入口，证明卡片编辑、模型提案、用户保存和刷新恢复均经过它；浏览器内 Markdown 与本地文件访问分别实现真实权限边界。单纯存储格式变更不承诺磁盘目录同步。
4. 按工作区切换主存储；迁移失败保持旧状态可用。原记录/原件原地保留为历史，不双写两个互相独立的正文。真实私人工作区迁移前提供具体备份和差异核对结果。
5. 跑上表相关回归、旧数据往返与浏览器验收，并用同一模型/合成材料验证 Markdown 上下文下的讨论、修改、引用、视觉理解和失败行为。

迁移保留结构化领域契约及字段身份，以无损 codec 将正文放进 Markdown，旧 repository 经共享入口读写同一版本；没有把所有记录压成固定两个文件，也没有永久双写同步系统。私人工作区仍按其首次访问分别触发迁移，不能以合成测试代替其实际核对结果。
