# Candidate 待确认信息与获奖卡片

2026-09-10。范围：个人材料导入后的 Candidate 工作区；不新增 Job 修改权限、跨卡片关系图或自动确认。

## 逐条回答

- 每个 OPEN uncertainty 可独立展开、输入并点击「回答」；其他问题可以留待以后处理。显示所属卡片标题与该卡片 grounding_refs 对应的文件名、材料位置。当前来源定位属于**卡片**，不是未经证实的问题级精确出处；来源缺失时明确提示，不显示内部 ID 或猜测项目。
- 目标绑定 source_document_id、Working ID/version/fingerprint、item_id、uncertainty_id 及当前问题文本。重复问题文字或不同卡片上相同 uncertainty ID 不会混为一条。提交前核对当前 Working，响应后继续经过现有版本、焦点、动作和持久化校验；旧版本/已处理问题拒绝调用 Provider。
- 专用入口固定 ITEM focus，并进一步拒绝修改其他卡片或其他 uncertainty 状态。模型理解回答、修改相关现有字段并在信息足够时解决所选问题；不足则保留 OPEN、解释或继续询问。代码不依靠年份/关键词决定语义，不自动解决问题，也不把故事内时间视为项目实际时间。
- 复用 Candidate 对话执行与 Working 持久化。回答和动作进入同源对话记录，修改只进入非权威草稿，Human Save 才生成确认版本。用户陈述不等于外部事实核验；旧 Working、确认版本与原材料保留。
- 空白回答不能提交；处理中阻止重复提交。失败在当前页面保留输入；未发送输入仅保存在页面内存，不承诺刷新恢复。成功修改后的 Working/问题状态可以刷新恢复。
- 卡片处于手动编辑时拒绝发出逐条回答，保留输入；对话处理中不再允许进入新的手动编辑。专用回答不附带主对话输入框中尚未发送的附件。

实现：[问题入口与目标守卫](../../public/candidate-clarifications.js)、[工作区接入](../../public/v1-pages.js)、[既有对话执行](../../public/candidate-workspace-conversation-runtime.js)。

## 获奖生成

- Model 导入 prompt 升为 `candidate_workspace_v3_atomic_awards`。AI 从材料理解独立奖项/比赛结果，一项一张；具体比赛/奖项名称作标题，已知模块与结果作副标题。区分入围与获奖，按实际证据保留年份、来源与未知，不把「获奖情况」栏目名当作重复标题。
- 同一结果的重复提及不重复建卡；不同比赛只有证据能独立支持时才拆分。只有笼统获奖声明但缺失具体奖名时，保守保留 OTHER/custom_section 与待确认问题，不伪造奖名、颁发方、年份或所属项目。
- 模型可以显式给出 `item_subtype`；前后端验证其与 item_type 的对应枚举。OTHER/award 由模型语义判断产生，不再必须依赖事实标签里的“奖”字。旧提案未提供 subtype 时保留原有兼容适配，不迁移旧资料或重写 Local 模式。
- 只改变后续生成规则，不静默重生成或替换用户现有卡片；真实材料仍走既有传输确认、生成草稿、人工核对和保存路径。合成文本模型测试不冒充真实简历或视觉 PDF 的重新分析验收。

实现：[生成与验证](../../src/candidate_context.py)、[浏览器提案验证](../../public/candidate-context-domain.js)、[Working 适配](../../public/candidate-model-runtime-domain.js)。
