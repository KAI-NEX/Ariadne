# 职位投递阶段

更新：2026-09-11。仅记录用户的跟进进度，不修改职位要求、个人资料或模型结论。

## 使用方式

- 职位描述库的每张职位卡片下方可选择：未投递、已投递、推进中、已结束。旧职位默认未投递，不推断真实投递情况。
- 已结束可选填结果：简历未通过、面试未通过、已入职、主动放弃、岗位关闭、其他结果；另可填最多 300 字备注。取消不保存，保存成功才更新列表。
- 默认「关注中」包含前三种阶段，不显示已结束职位。可按四个阶段或「全部」筛选；已结束不删除卡片，随时可切回其他阶段。
- 重新开启清除当前结束结果，但保留用户备注及旧阶段历史。卡片正文仍打开原职位详情；阶段按钮不触发详情。

## 数据与边界

- `job-application-domain.js` 以稳定的 `job_context_id` 关联记录，独立存于同 origin 的 IndexedDB `ariadne-job-applications-v1/applications`，不升级或改写原资料库。职位内容更新不会改变跟进记录。
- 当前阶段、结果、备注、修订号和追加历史在同一事务保存；使用期望修订号校验，陈旧页面不能覆盖新记录。保存失败保留原记录与表单；同源页面通过 BroadcastChannel/焦点恢复刷新。
- 只在用户点击保存后写入，不发起模型请求，不把拒绝结果推断为缺少能力。不自动投递，不读取邮箱，不自动判断结果。
- 刷新保留数据，但不跨浏览器、设备或 origin 同步；浏览器数据被清除仍会丢失。历史目前作为持久化记录保留，没有新增历史浏览页面。
- 本阶段只筛选职位库展示，不改变「了解职位概况」或其他 AI 对话的上下文范围。后续若需要仅讨论在跟进的职位，应另行明确范围与版本契约。

## 验证

- `tests/job_application_regression.mjs` 覆盖阶段、结果约束、筛选、原状态不可变性、重新开启历史和修订冲突；完整离线回归 94/94 通过。
- egolite 验证阶段保存与结束隐藏；截图接口超时后，隔离 Chrome 补验刷新、取消、重开、跨页冲突、存储事务失败、页面恢复及桌面/390 px 呈现。浏览器合成数据与 QA 留在 `.cache/job-stages-20260911/`，未操作真实用户职位、调用模型或发送 POST。
