# Ariadne 真实用户验证协议 v1

状态：**计划就绪，尚未执行**。日期：2026-09-20。本文件不是用户研究结果。

## 决策问题

目标求职者能否借助 Ariadne 完成有来源的岗位判断？与已有方式相比，哪里更可靠，哪里增加了负担？本轮不验证录用率，也不证明商业可行性。

## 人群与样本

首轮建议 5–8 位近期正在求职、已有经历材料和具体目标岗位的人；记录是否认识维护者、AI 使用熟练度、求职阶段。样本用于发现问题，不用于估计市场成功率。不要只邀请 AI 开发者或只收集熟人赞美。

## 先确认数据使用

说明研究用途、预计 40–50 分钟、可以跳题或中止；是否录屏另行同意。优先由参与者在自己的设备操作脱敏副本和自己的模型连接，发送材料前遵守产品的 Provider/传输/费用确认。不索取密码或 API Key，不替参与者作出传输同意。

不同意使用个人材料时，可选合成材料，但结果标记为合成任务，不宣称验证了个人求职价值。研究记录与真实材料存入私有位置，不进入本仓库。引用、截图和公开案例另行取得同意，并约定保留/删除期限。

## 单场流程

1. **5 分钟背景访谈**：最近一次判断岗位是否适合时怎么做？花了多久？哪里最难？先问实际经历，不演示方案。
2. **5 分钟首次上手**：从产品入口开始，观察是否理解、能否连接和导入。记录需要帮助的步骤；无法接入也是产品观察，不从样本中删除。
3. **20–25 分钟任务对比**：用现有方法与 Ariadne 分别完成一项可比任务。尽量匹配底层模型、源资料长度、任务难度及时间预算；记录不能控制的差异。
4. **5–10 分钟回访**：哪里有用？哪条不可信？你会保留哪个结果？什么情况下不会再用？不要问“是不是更好”。
5. **下一次真实求职任务**：参与者愿意时观察 7–14 天内是否有任务、是否主动复用；没有求职任务不等同于拒绝产品。联系跟进需事先同意。

任务卡：“请判断这份岗位与你的经历的关系：找出三条有材料支持的要求、两条仍不确定的内容，并提出一个合理下一步。每个结论说明依据。材料不支持时请保留未知，不必凑够三条。”

## 比较方式与学习效应

优先准备两组难度相近的材料/岗位任务 X、Y。奇数组先原方式 X、再 Ariadne Y；偶数组先 Ariadne X、再原方式 Y，记录顺序。小样本仍无法完全控制难度与学习效应。

如果只能用同一份个人材料与同一 JD，交叉安排工具先后，明确第二轮可能受第一轮启发，不把差异归因全部交给产品。原方法不能使用相同模型时，结论标为“整体工作流比较”，不能宣称隔离出了 Ariadne 的产品效果。

## 预先固定的判断标准

| 观察项 | 如何记录 |
| --- | --- |
| 独立完成 | 无操作提示完成；有提示完成；未完成。分别列出人数，不将有帮助算独立完成 |
| 有来源的正确判断 | 逐条核对原材料/JD，标记支持、矛盾、信息不足；争议单列 |
| 无依据的确定性断言 | 记录条数、总受检断言数、严重程度与具体错误类型 |
| 可核对性 | 参与者能否找到支持结论的原文；记录误引、找不到和未知 |
| 总投入 | 接入耗时、任务耗时、核对修正耗时分别记录；失败/中止记录时点，不只统计成功样本 |
| 成本 | 有实际用量/账单才记录实际成本；估算单列，缺数据写 unknown，不把未见费用记零 |
| 复用 | 下次是否有真实任务、有任务时是否主动复用、原因；保留未回复 |

研究者基于原文作初评，参与者核对其经历含义；尽可能对争议与严重错误进行第二人复核。AI 可以辅助整理，不是唯一裁判。评价“有依据”，不是评价该人是否应被公司录用。

## 怎样形成闭环

1. 将发现分为需求不成立、上手障碍、模型理解、来源/上下文、交互、人审负担；关联匿名 session ID。
2. 按影响和重复性选一个主要问题。涉及不知情传输、无依据内容被当成确认事实等严重问题时先修复，再继续同类任务。
3. 在动手前写下“修改什么、预计改善哪个观察项、什么退化不可接受”。
4. 只改选定问题，保留版本；同一任务标准复验，既检查目标改善，也检查事实和来源是否退化。
5. 使用原参与者观察修正是否生效，另找少量新参与者检查初次使用；两类结果分开，不把熟练后的提升当新手成功率。
6. 发布匿名汇总：实际人数、失败与退出、版本、样本局限、负面结果、下一决策。没有足够证据时结论可以是继续探索、缩小人群或停止某项功能。

本轮完成的定义是：有可核对观察、一个有依据的产品决定和复验结果；不是所有人称赞，也不要求指标必须上涨。不要事后调整成功标准来美化结果。
